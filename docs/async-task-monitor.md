# 异步任务状态跟踪

## 行为

平台接受任务并返回任务 ID 后，后端自动登记状态检查。等待、查询和重试由 Python 代码执行，Agent 不调用 sleep，也不循环调用状态工具。

- 默认在提交后 60 秒检查一次，此后每 180 秒检查一次。
- 成功、失败或取消后停止查询。查询接口超时、鉴权失败或返回未知状态，都不会把平台任务标记为失败；重试间隔逐步延长，最长 300 秒。
- 没有到期任务时不请求平台。没有状态变化时不向对话追加消息。
- 新提交的正式工作流默认只通知结果，不启动新的模型回答。用户明确要求分析结果或执行后续步骤时，提交工具设置 `continue_after_completion=true`；完成后由后端恢复执行，当前轮仍然结束。
- 继续执行遵循原用户要求，不因训练完成而自动增加评测或重训。
- 恢复历史正式工作流时，若没有明确保存的后续执行要求，只更新状态和通知，不补启动分析或评测。

支持已有平台任务类型：正式工作流、工作流调试、数据清洗、数据准备、环境处理及其渲染和汇总任务，以及等待平台工作流的 graph 节点。本地经验回放不使用平台任务查询。新任务类型需要提供可靠的任务 ID、状态查询方式，并明确接入监控。

## 执行链路

```text
提交工具 → 平台返回任务 ID → 保存外部任务和检查时间 → 当前轮结束
                                      ↓
独立调度 Worker → 受保护的内部接口 → Runtime 检查到期任务
                                      ↓
                      平台状态接口 → 保存结果 → 原对话事件
```

Worker 是独立 Python 进程，默认随后端启动，由后端监督退出重启；关闭后端时一并停止。它每 5 秒联系一次本机内部接口，有到期任务才查询平台。查询和结果交付在 Runtime 中执行，从而复用原进程的会话事件订阅及内存凭据。独立 Worker 负责调度，平台 HTTP 查询仍由后端异步代码执行。

默认的完成通知直接保存为原对话的消息，并通过现有 SSE 事件发送。页面关闭时结果仍会保存，重新打开对话后可以读取。需要继续执行时，复用 Harness 的外部任务通知；已释放的会话在凭据可用时重新连接。正在执行的 Pi 会话使用已有通知队列，不启动并发执行。

内部接口需要专用随机凭据，不对 Agent 暴露。Worker 通过环境变量接收凭据，不写入任务记录。

## 持久化与重启

外部任务沿用 Product Store；检查时间、失败次数和执行租约保存到 conversations 目录下的 `.task-monitor.sqlite3`。租约避免多个调度请求重复领取任务，检查进程退出后可以重新领取。启动时从已有 Product 快照补齐遗漏的待检查任务。

每个任务保存提交时的集群标识，后续切换页面区域不改变这个任务的查询目标。Cookie、Authorization 和平台密钥不进入任务记录或检查数据库。

用户凭据只保留在后端内存中，因此关闭浏览器不会立即停止跟踪；后端重启或凭据失效后，需要用户重新访问原对话、提供有效登录凭据后才能继续正常查询。检查记录不会丢失；缺少凭据时不请求平台，凭据失效导致的请求失败按退避间隔重试。完全无人值守、跨后端重启的查询需要后续接入可刷新凭据的服务身份，当前不通过落盘用户 Cookie 实现。

SQLite 租约用于协调检查，不代表支持任意多副本部署。默认部署为一个后端实例及其 Worker；多副本需要共享任务存储，并将检查请求路由到拥有对应会话凭据的实例。

## 配置

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| `PYROMIND_TASK_MONITOR_ENABLED` | `1` | 是否启用跟踪 |
| `PYROMIND_TASK_MONITOR_FIRST_DELAY` | `60` | 首次查询延迟，秒 |
| `PYROMIND_TASK_MONITOR_INTERVAL` | `180` | 后续查询间隔，秒 |
| `PYROMIND_TASK_MONITOR_AUTOSTART` | `1` | 是否由后端启动 Worker |
| `OH_INTERNAL_SERVER_URL` | 启动命令的本机地址 | Worker 联系的后端地址 |
| `PYROMIND_TASK_MONITOR_TOKEN` | 进程内随机生成 | 内部接口凭据 |

正常使用原启动方式即可，无需修改 `start_inference.sh`，也不需要 Celery、Redis 或 Kafka。

若由进程管理器单独启动 Worker，将 `PYROMIND_TASK_MONITOR_AUTOSTART=0`，并向后端和 Worker 提供同一个 `PYROMIND_TASK_MONITOR_TOKEN`：

```bash
uv run python -m pyromind_agent_server.task_monitor_worker --url http://127.0.0.1:8000
```

现有平台状态接口返回任务及节点状态，监控不会额外拉取节点日志或训练产物。普通状态查询不调用模型，不消耗模型 Token。
