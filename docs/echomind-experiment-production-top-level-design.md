# EchoMind 实验与正式运行顶层改造方案

> 方案对齐稿 · 2026-11-03
>
> 根据两份会议记录整理，以本轮明确结论为设计前提：实验阶段最终验证通过的 Dataset → Train → Eval 可以整体直接复用于正式阶段。本文只讨论产品定位、职责和流程，不涉及接口、存储或实现细节。

## 1. 结论：调整生命周期，保留现有实验底座

现有设计不需要整体推翻。实验自由探索、参考 Graph 不阻塞执行、基模 baseline、真实评测、任务恢复等方向继续保留。

需要调整的是实验的交付目标：**实验结束时，既得到模型和效果结论，也得到一套已验证、能够在新数据上重复执行的 Dataset → Train → Eval 流程。正式阶段直接运行这套流程，并接入线上数据与模型更新闭环。**

会议中的 Demo 主要展示固化后的正式运行。它应作为正式阶段的目标样例，实验阶段继续保持探索空间。

## 2. 一个产品，三个连续环节

| 环节 | 核心问题 | 主要行为 | 交付结果 |
|---|---|---|---|
| 实验探索 | 怎样才能达到业务目标？ | 探查数据、尝试处理方式、训练、评测、分析并调整 | 验证通过的流程、模型和效果证据 |
| 方案固化与发布 | 最终选用哪套方法，正式如何运行？ | 选定有效流程，明确数据要求、运行参数及更新规则 | 可正式运行的方案 |
| 正式运行 | 怎样在持续到来的数据上重复优化？ | 采集数据、重复执行、比较结果、按规则更新模型 | 持续运行记录、在线模型和周期报告 |

固化发生在实验取得有效结论之后。实验中不要求反复确认 Graph 版本，也不要求先填完整张图才能执行任务。

## 3. 实验阶段：继续围绕任务自由探索

```text
用户目标 + 初始模型 + 用户提供的数据
                  ↓
             Init：基模 baseline
                  ↓
         Dataset → Train → Eval
             ↑              │
             └── 分析、调整 ──┘
                  ↓
        达到目标后选择最终有效方案
```

Init 仍是实验阶段中的一个 Stage，使用 Eval 能力完成基模评测；已有可信 baseline 时可以复用。它不要求在每次迭代或每轮正式运行中重新执行。

实验以用户提供的数据为起点，允许清洗、筛选、合成、补充监督信息和形成新数据版本。Manager 可以跳过步骤、重跑训练、只做评测或调整训练方式，不受参考图完整程度限制。

Train 可以包含 SFT、GRPO 或二者组合。一次实验可以有多轮尝试，最终只选择已经验证过、准备继续使用的流程进入正式方案。失败尝试和临时分支作为实验历史保留。

## 4. 复用边界：同一套核心流程，接入不同来源的数据

| 内容 | 实验阶段 | 正式阶段 |
|---|---|---|
| 数据来源 | 用户提供的原始数据及实验派生数据 | 线上业务与 Tracer 持续采集的数据，也可补充人工数据 |
| 数据接入 | 将用户数据整理为本方案约定的输入 | 将线上数据整理为同一方案约定的输入 |
| Dataset | 探索并验证清洗、筛选、合成、采样及监督数据准备方法 | 直接复用选定的方法，处理新一批数据 |
| Train | 验证训练方式、训练流程及参数 | 直接复用选定训练流程，使用本轮数据与指定起始模型 |
| Eval | 验证评价口径，比较 baseline 与候选模型 | 复用同一口径，比较当前在线模型与候选模型 |
| 推进方式 | Manager 根据结果选择下一步 | 按发布方案及运行规则持续推进 |

**复用的是最终验证过的执行流程，包括必要的处理逻辑、训练方式与评价规则；数据、模型和允许调整的参数是每轮输入。**

因此，实验阶段就需要验证“这套方法能否换一批符合要求的数据继续运行”。正式阶段不再重新设计 Dataset、Train、Eval，也不重新走一遍所有历史试错。

拒绝采样、错题筛选、采样比例等属于具体方案的数据策略。AVI Demo 中的某个比例或训练方式不升级为所有 EchoMind 场景的固定规则。

## 5. 正式阶段：在核心流程外补上线上闭环

```text
线上业务 → 常驻 Inference → Tracer 采集
                ↑              │
                │         数据积累与接入
                │              ↓
                │   复用 Dataset → Train → Eval
                │                          ↓
                └── 模型入口切换 ← 更新判定
```

正式阶段新增或补齐以下职责：

- 维护当前对业务提供服务的模型入口。
- 从业务运行中采集数据，按约定条件组织新一轮处理与训练。
- 重复运行已发布的 Dataset → Train → Eval。
- 根据评测结果和发布规则决定是否替换在线模型。未达要求时继续使用当前模型。
- 提供每轮结果、周期分析、异常说明和人工调整入口。

模型更新需要区分“候选模型已评测”“允许替换在线模型”“业务入口已经切换”三个事实。不能仅凭训练成功或一个指标上涨就默认完成替换。

评测内部为候选模型启动的推理能力，与对业务常驻服务的 Inference 有不同用途和生命周期。前者继续属于 Eval 的执行过程，后者承担线上服务；不把它们合成同一个业务阶段。

## 6. Graph、Agent 和执行的定位

| 对象 | 定位 |
|---|---|
| 实验参考 Graph | 为探索提供方向，可不完整、可调整，不承担审批与执行前置条件 |
| 正式 Graph / 流程 | 表达已发布方案的稳定执行关系，以及采集、触发、模型更新等运行规则 |
| Manager | 理解目标、协调工作、分析结果、解释异常和辅助调整 |
| Dataset / Train / Eval | 三类专业业务职责，可由对应能力或角色完成；阶段不等于 Agent |
| 平台执行能力 | 运行已选定的处理、训练、评测和服务任务，提供实际状态与产物 |

沿用当前仓库中 Manager 直接执行、按需委派 Eval 的能力，不以强制拆出更多子 Agent 为本次改造前提。后续按原计划补齐 Dataset、Train 的专业能力。

正式阶段的固定任务按已发布流程执行，Agent 不需要每轮重新规划或编写执行内容。Agent 持续提供结果解释、周期报告、异常分析及变更建议，也可以在用户要求时介入处理。

现有执行底座及插件集成、任务恢复、数据库双后端和 Pyromind/EchoMind 隔离继续保留。

## 7. 固化内容与正式调整

实验结束后，选定以下内容形成正式方案：

1. 业务目标、适用范围和效果证据。
2. 最终验证过的 Dataset → Train → Eval 流程。
3. 数据要求，以及所选训练、评测方式需要的标签、正确答案或监督轨迹。
4. 初始模型、评价口径和对照方式。
5. 数据积累、运行触发、模型更新与暂停规则。
6. 可调整的参数范围和报告要求。

正式阶段允许人工调整。buffer 大小、触发条件及已验证范围内的训练参数可以按运行规则变更，后续轮次使用新设置，保留变更记录。

Prompt、reward、新故障类别等也允许调整，但需要针对影响验证，再更新正式方案。改变数据处理方法、训练组合或评价含义等较大变更时，回到实验验证后再发布。

**固化意味着方法已验证、运行可重复，并保留受控调整能力。**

## 8. 报告与前端

评测统一交付平台约定的标准结果，覆盖输入范围、指标、逐样本证据、错误和产物引用。Agent 基于这些事实给出解释，页面负责展示，结果生产与渲染分开。

业务采集轨迹、模型预测与 SFT 所需的正确监督轨迹需要明确区分，不能因为都称为“轨迹”就互相替代。平台标准产物的正式名称与展示内容在后续对接中确定，本次不预设具体格式。

前端保留对话为主：

- 实验中重点展示当前任务、真实结果、对比和阻塞，参考图作为辅助。
- 发布时展示将复用的流程、输入要求和运行规则，进行一次明确的发布确认。
- 正式运行中展示在线模型、数据积累、最近几轮效果、运行状态及调整入口。

## 9. 改造顺序与对齐事项

继续沿用现有六步主线，先补齐 Dataset、Train 和训练后 Eval，完成一轮真实实验。随后增加“实验结束整理并发布可复用方案”，再接入线上数据采集、常驻 Inference、运行触发及模型更新。先验证一次正式运行，再验证持续多轮运行。

第一轮复用验收标准是：**将实验验证过的流程用于另一批符合要求的数据，不重新设计流程，即可完成 Dataset → Train → Eval，并得到可比较的结果。**

本轮建议确认以下产品边界：

- Dataset → Train → Eval 整体直接复用，作为本期设计前提。
- 正式数据的来源和监督信息如何获得，特别是 SFT 的正确轨迹与 GRPO 的正确答案或奖励依据。
- 正式运行在什么条件下启动，模型更新需要哪些指标与业务限制。
- 哪些参数可直接调整，哪些变更需要补充验证。

具体采样策略、更新阈值和报告格式继续由场景与平台约定，不阻塞此次生命周期与复用边界的对齐。
