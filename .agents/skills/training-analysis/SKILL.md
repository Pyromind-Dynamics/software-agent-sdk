# 训练分析

通过 `training_analysis` 完成训练 run 的定位、指标探查、诊断和报告。认证、
数据源连接和临时文件由服务端管理，不向用户索取，也不在回答中展示。

## 训练产物

训练完成后用 `operation="artifacts"` 读取实际任务的 output_path，发现所有
checkpoint-n 与 eval_step_n.jsonl；不依赖 W&B。多个训练节点时用
`training_node_id` 明确目标。返回文件指纹、样例、字段和模型完整性；不能将
不同 step 的 eval 与 checkpoint 配对。路径未解析或文件不可访问时按缺口处理。

已有 eval 交给 [inference-evaluation](../inference-evaluation/SKILL.md) 的
已有预测评分入口：读取真实样例后生成一份评分脚本，计算所有 step，并复用基线预测。
逐条预测的类别、格式和错误数量以该入口的固定评分结果为准；不能在本 Skill 中
用 terminal 临时解析后报告全量统计。若只查看了部分样本，只能作为线索，不能
推算全量比例；报告数量时核对分母及各分类数量之和。
结合实际训练 step 的 W&B 序列解释选择；log_step 不等于 checkpoint step，未记录值不等于 NaN。

## 指标分析

1. **探查**：调用 `training_analysis(operation="probe", task_id="...")`，确认
   目标 run、可用指标键和配置键。
2. **分析**：SFT 等同时记录训练和验证 loss 的任务，调用
   `training_analysis(operation="analyze", task_id="...", metric="train/loss",
   keys=["train/loss", "eval/loss", "train/grad_norm", "train/learning_rate"])`。
   `metric` 决定主要诊断对象，`keys` 用于并排查看曲线（最多 20 个）；分别说明
   train/loss 与 eval/loss 的点数、最低点、末值和走势，不要把两者当成同一指标。
   同时区分逐 step 的 `train/loss` 与汇总指标 `train_loss`；不能用最后一个
   train/loss 点代替全程训练损失。工具默认返回曲线摘要和关键配置；只有需要核对
   单个 step 时才传 `include_history=true`，不要把完整配置或所有点复制到结论中。
3. **报告**：需要可复用的 Markdown 结论时，明确指定验证指标，例如
   `training_analysis(operation="report", task_id="...", metric="eval/loss")`，
   避免报告默认指标与 analyze 的主指标不同。可选的 `output_path` 必须位于
   `public_data/training-analysis/`；未指定时使用默认报告路径，并在结果中返回
   `report_path`。

`output_path` 仅适用于 `operation="report"`；调用 `probe`、`analyze`、`artifacts`
时省略该字段。工具参数校验失败时先删除不适用字段再重试，不要原样重复调用。

`run_url` 只能作为已有 `task_id` 的定位提示，不能替代 task_id。一次分析只
针对一个 task。先探查再选择指标，避免请求无关的大量 history。

## 跨任务对比

先用明确的 task_id 分别分析基线和待比较任务，再核对验证数据及样本数、指标定义、
模型与训练配置。只有验证数据和指标口径一致时，才用指标数值判断哪个任务更好；
条件不同时，列出差异，说明哪些趋势仍可比较，不把 loss 数值差异归因于单个参数。
报告中写明基线 task_id、实验 task_id、验证数据口径和主要配置差异；缺少可比基线时
只分析当前任务，不虚构对照结果。

## 结论与后续

说明指标趋势、NaN/尖峰、发散、收敛和过拟合信号，并把结论与配置变化对应起来。
Loss 的数值或恰好为整数不能证明它是错误样本计数；未取得指标定义时只描述
数值和走势，不推断“错了几条”或评估脚本有问题。
验证 loss 有波动时先看后段整体走势，不因末尾几个点高于单个最低点就判定持续回升。
只有末尾多个点持续、明显超过此前低谷附近的波动范围时，
才报告“当前验证数据上观察到回升迹象”，并列出最低点、末值和对应 step。
这也包括升高后维持在高位的情况；不要把高位平台写成仍在持续上升。
如果此前已经在高低区间反复切换，且高位后再次回到原范围，末尾回到高位
不能单独算作新的持续回升。判断幅度应结合当前 loss 的量级和波动范围。
一直在同一范围内上下抖动时，描述为“验证 loss 波动，未见明确持续回升”；
首尾一段的水平明显下降时，描述为“有波动但整体下降”；其余情况如实描述
趋于稳定或趋势不确定。
回升迹象可能与过拟合或训练不稳定有关，不能只凭单一 loss 确认泛化能力变化或
原因。只有 train/val 差距也扩大且验证集规模足以支撑判断时，才把过拟合作为较强结论。
样本很少时明确说明：多个 eval step 是对同一小验证集的重复测量，不代表有更多独立验证
样本；不能据此确定最佳 checkpoint。若只有 2 条验证样本，应建议用更大的独立验证集复核。
报告不得在观察到验证 loss 回升迹象时写“未发现明显异常”。调参建议必须对应实际观测到的
问题：验证 loss 有回升迹象时优先建议用较大的独立验证集比较最低点与末尾 checkpoint；没有数值
异常或发散证据时，不要自动建议降低学习率、减小 batch 或增加 epoch。
报告出现数据异常或调优收益不稳定时，建议继续检查训练数据质量（空值、重复、
格式、标签分布和异常样本）。需要补数据时，将训练证据、数据来源和待验证的
假设交给 [data-processing](../data-processing/SKILL.md)：先检查源数据并确认
Gap，再进入 [合成范式](../data-processing/references/paradigms/gap-driven-synthesis.md)
选择合成方法、试跑和复核。
loss 只能提示问题，不能证明某个类别缺样，也不能直接据此决定扩增数量。
执行训练的完成回调还需按原任务衔接 [inference-evaluation](../inference-evaluation/SKILL.md)：
用户未排除评测时，先复用训练 eval 产物选择 checkpoint，已有基线按同口径复用评分。
仅对已有 train + val 预测评分时不新增模型推理；更换或扩大验证集时，旧预测不含
新样本，需先让候选 checkpoint 对新验证集推理，再按同一规则评分。用户明确本轮
不做新推理时，只说明后续所需步骤，不把旧预测重评说成新验证集评测。
独立 test 在验证集选模后使用所选 checkpoint 推理评分，不参与选模；LoRA 合并所选 step。
人工打标交给 [label-studio](../label-studio/SKILL.md)，用 `label_studio_project`
导入已有 badcase；不以分布分析、重新评分或完整评测报告作为打标前置条件。
已有可比基线直接复用。只分析已有 run 或明确不评测时不新增任务；缺少验证集、GT 或可用产物时
说明缺口，不以训练集或训练 loss 宣称效果通过。W&B 取数失败不阻止已有模型产物的效果评测。
训练参数调整仍按单变量探针进行；用户确认后交给工作流生成能力，并在新
task 完成后重新分析。

## 最终回答

先直接回答用户关心的判断：训练是否完成、当前证据支持什么结论、能否据此选模或
判断效果。随后只给支撑判断的关键指标及对应 step，说明验证集规模和其他会影响
判断的证据缺口，最后给出一个最优先的验证动作及其目的。区分观测事实、可能解释
和已确认结论；证据不足时直接说暂时无法判断，不用含糊的“整体正常”代替结论。
默认用简短文字概括，不复述完整配置或逐点曲线；用户要求细节时再展开。

若 `report` 自动正文与已核实的指标相矛盾，以实际指标为准解释，并说明报告中
哪项判断需修正，不把冲突的报告结论直接转述给用户。报告路径作为证据入口给出，
不能代替面向用户的结论。
保留 `report` 生成的原文件；需要补充人工解读时在回复中说明，或另存补充报告，
不要覆盖原报告路径，以便复核自动报告与人工判断。

训练分析取数只使用 `training_analysis`，不调用 terminal 或直接运行本 skill
下的脚本，不手工传递认证信息、保存临时认证文件或直接访问 W&B。
交接后的数据处理执行方式以 data-processing 的工具与 SOP 为准。
