# 四阶段分析方法论

从 wandb 数据中得出可行动结论的流程:先验 → 惊奇 → 机制 → 可证伪探针。

## 1. 先验(Prior)

分析前明确预期,避免被数据牵着走:

- 训练类型决定基线预期:SFT 期望 loss 单调下降后平台期;DPO 期望训练/验证 gap
  可控;GRPO 期望 reward 稳步上升、KL 可控。
- 记录当前 config(learning_rate/batch/epoch/LoRA rank/model)与数据规模,
  它们构成"为什么是当前表现"的先验解释。

## 2. 惊奇(Surprise)

用数据挑出与先验不符的点:

- **稳定性**: NaN 数、尖峰数、发散(最终值 vs 最小值差距过大)。
- **收敛状态**: 最终值是否已进入平台期,或仍在下降(欠训)。
- **对比差异**: 与相邻 run/基线 run 的 config diff 与指标差异。
- **system 指标**: GPU 利用率异常(闲置/过载)。

## 3. 机制(Mechanism)

为每个惊奇点给出可检验的机制假设,不臆测:

- NaN/发散 → 学习率过大 / 梯度爆炸 / 数据含异常样本。
- 高频尖峰 → 学习率过高或 batch 过小,梯度方差大。
- 平台期过高 → 模型容量不足(LoRA rank 过低)/ 数据质量 / 欠训练。
- 训练/验证 gap 大 → 过拟合(epoch 过多 / 数据量小)。
- GRPO reward 崩溃 → 奖励尺度 / KL 惩罚不匹配。
- 对比 diff 中哪个参数变化最可疑,优先从它切入。

## 4. 可证伪探针(Probe)

每轮只改一个变量,实验必须能推翻机制假设:

- 参数修改幅度要能产生可观测差异(如 lr 减半、rank 翻倍),但保持单变量。
- 记录基线 run id 与探针 run id,新 run 完成后用 `compare-runs` 验证。
- 无效即放弃该机制,换下一个;有效则收敛或继续沿该方向微调。

## Pyromind 场景要点

- SFT: 关注 `train/loss` 平台期高度与到达步数;平台期未降时可试更低 lr + 更多 epoch。
- DPO: 关注训练/验证 loss 与 gap;reward 曲线收敛性比 loss 绝对值更重要。
- GRPO: 关注 reward 是否崩溃/震荡;KL 与 reward 的平衡是首要检查项。
- LoRA vs Full: 同数据下对比收敛速度与最终 loss,判断容量瓶颈。
